# CIS simulator (gate G2)

A discrete-event simulator for checking the CIS Central engine in `..` (the parent directory) without hardware.
Link-layer specification: [`docs/c6-link-layer.md`](../../docs/c6-link-layer.md). G2 is the simulator's pass
gate, defined below.

Principle: **independent implementations of the same specification**. The reference Peripheral, AES/CCM, CSA#2
and the air model are written only from the Core specification (5.3+: Vol 6 Part B 4.5.13-14, 2.4.2.25-29, Part E,
Vol 4 Part E), without reading `cis_engine.c`/`cis_proto.c`/`cis_crypto.c` or the Zephyr code. Only the contract
headers `cis_platform.h` and `cis_engine.h` are shared.

## Running

```sh
docker run --rm --entrypoint bash -v "$PWD:/src" espressif/idf:v5.5.5 -c "sh /src/cis_ll/sim/run.sh"
# (from the repository root; Git Bash on Windows: MSYS_NO_PATHCONV=1 and "$(pwd -W)")
```

`run.sh` builds two programs (gcc C11, `-Wall -Wextra -Werror`, ASan + UBSan):

1. `out/sim_ref` = simulator + `test_central.c` (a small scripted Central used ONLY to self-test the harness):
   unit tests on specification vectors + scenarios + negative tests (does the simulator detect errors).
2. `out/sim_eng` = simulator + the engine `../*.c` (when `cis_engine.c` exists), otherwise the stub
   `stub_engine.c` (then the results mean nothing). G2 scenarios: `--all`.

Logs: `out/logs_ref/<scenario>.log`, `out/logs_eng/<scenario>.log` (violations with time and
details, the first 30 of each kind). Only summaries on screen. A single scenario:
`out/sim_eng --scenario loss1 [--seed N] [--time S] [--loss P] [--max-nse N] [--owns-seq 0|1] [--coex D]`.

## What is inside

| File | Contents |
|------|----------|
| `sim_core.c` | event heap (int64 ns time), clocks with drift (ppb), xoshiro RNG, log, violation counters |
| `sim_crypto.c` | own AES-128 (FIPS-197), BLE AES-CCM (M=4, L=2), nonce, SK = e(LTK, SKDp\|\|SKDc) |
| `sim_phy.c` | CSA#2 with subevents, AA rules, air time at 1M/2M, losses/CRC, Wi-Fi coexistence windows |
| `sim_periph.c` | **reference Peripheral**: LLCP (ENC, CIS_REQ/RSP/IND/TERMINATE, REJECT_EXT), CIS events with window widening, channels, SN/NESN/CIE/NPI, FT, CCM, uplink, strict checks |
| `sim_acl.c` | ACL (anchor, counter, SN/NESN, retransmission, LLCP in successive events, DLE 27->251), the rest of the C6 controller (LE Enable Encryption, Disconnect ACL, supervision) |
| `sim_platform.c` | `cis_platform_ops_t` + an ideal radio (prepare_tx/rx_done/event_closed/event_skipped in simulated time, radio reservations, collisions with the ACL) |
| `sim_host.c` | P4 host: HCI like a BAP client, an SDU every 10 ms with SDIO jitter and stalls, NOCP, uplink |
| `sim_main.c` | scenarios, metrics, the G2 verdict |
| `test_central.c` | self-test ONLY: a scripted Central (BN=1, FT=1, NSE<=3) |
| `stub_engine.c` | ONLY for building without the engine |

## Model (summary)

- Real time in ns; the C6 and each earbud have their own clock with drift; the C6 clock starts 40 s before the
  uint32 us wraparound (a test of signed comparisons). The host paces SDUs with the C6 clock (as with ISO TX Sync).
- Air: packet loss `loss`, of which `crc_frac` with a CRC error (AA detected, the Peripheral responds), the rest
  without AA. Coexistence: the C6 radio is busy in 1-6 ms windows with a given share (the C6 neither
  transmits nor listens).
- C6 radio: a CSA#2 channel with the AA and channel map of the link, transmitting exactly at anchor + se*Sub_Interval
  of the C6 clock, the Peripheral responds after T_IFS by its own clock. A subevent reservation = the time of the max
  C->P PDU + T_IFS + the max P->C PDU; a collision with an ACL reservation (2 x 27 B + MIC + T_IFS) or another CIS ->
  the subevent is not served and the `ovl` counter increments. `radio_owns_seq = 1` models the ACL sequencer (NESN
  toggles on every new packet, also a null PDU; SN on ACK; no shifting at the flush point).
- The Peripheral checks: LLCP format (lengths, RFU), LL_CIS_REQ parameters per the spec and the host request,
  CIS_Offset within the range from LL_CIS_RSP, AA, synchronization delays, the instant of the first anchor, the timing
  of every packet within a window of +-(SCA_C + SCA_P) * time since synchronization + 2 us, the subevent channel, PHY,
  header (LLID, NPI, RFU, length with MIC), SN/NESN per the CIS rules, MIC, SDU content and order.
- SN/NESN rules (interpretation of Vol 6 Part B 4.5.13): payload p has SN = p & 1; after the flush point both
  sides shift SN/NESN as after an ACK; null PDUs (NPI) are not acknowledged and do not shift NESN.
  CIS IV = ACL IV with the 32 low bits XORed with the CIS AA; nonce from cisPayloadCounter, direction 1 = C->P.

## Metrics and verdict

`ev` CIS events per earbud, `miss` events without any packet, `skip` event_skipped, `loss` SDUs
not delivered / generated by the host (including those rejected for lack of credits), `late` SDUs delivered
one event later than the first (unsteady latency), `lat` from generation to the SDU synchronization point
(anchor + CIS_Sync_Delay + (FT-1)*ISO), `underrun` events with a PDU without data during the stream,
`flushC` C->P payload slots without received data, `up` uplink at the host, `ovl` CIS/ACL and CIS/CIS collisions,
`engine stats` = `cis_engine_get_stats` (compared with the truth from the air).

PASS (G2) = handshake, >= 10 000 events, loss within the scenario threshold, zero violations of every category
(format, timing, channel, MIC, SN/NESN and counter, LLCP, parameters, contract, HCI), zero collisions, zero `late`,
zero underruns, links closed, zero duplicate SDUs.

| Scenario | Description | Loss threshold |
|----------|-------------|----------------|
| ideal | no losses, small drift, clock wraparound | 0 % |
| loss1 | 1 % losses | <= 1 % (G2) |
| loss5 | 5 % losses | report |
| drift | +50/-50 ppm, 30 min (180 000 events) | 0 % |
| coex10 | Wi-Fi 10 % of the time, 1-6 ms windows | report |
| hostjitter | SDIO 0-3 ms + 0.5 % of 8 ms stalls | 0 % |
| twobuds | 2 ACL + 2 CIS in one CIG, 1 % losses | <= 1 % |
| nse1 / nse3 | radio max_nse 1 / 3 at 5 % losses | report / <= 1 % |
| reject | the Peripheral answers LL_REJECT_EXT_IND (0x0D) | CIS Established with status 0x0D |
| aclloss | the earbud disappears at 20 s | CIS Disconnection Complete at supervision + 1 s |
| hwseq | radio_owns_seq (ACL sequencer), 1 % losses | <= 1 % |
| noenc | no encryption | 0 % |
| neg_* | negative harness tests (MIC, timing, channel, sequencer) | must detect a violation |
